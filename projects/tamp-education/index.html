Project Overview: TAMP Education — Digital Education Platform

The TAMP Education website is an education-focused digital platform designed to provide students, visitors and prospective users with an accessible, responsive and engaging online experience.

The project focuses on presenting educational information through a clear content structure, responsive layouts, intuitive navigation and accessible user experiences across desktop and mobile devices.

The application is version-controlled through GitHub and packaged with Docker. Kubernetes and Minikube are used locally to understand and test container orchestration concepts, while GitHub Actions automates the CI/CD workflow.

Terraform is used as Infrastructure as Code for the AWS environment, with Amazon S3 providing storage and Amazon CloudFront providing global content distribution.

The website is also being developed as a practical DevOps and cloud deployment project. The development workflow connects source control, containerization, local Kubernetes testing, CI/CD automation and Infrastructure as Code.

Development & Deployment Workflow

The intended engineering workflow is designed to validate changes progressively before production deployment.

  • Developer pushes changes to GitHub.
  • GitHub Actions starts the CI/CD workflow.
  • Application files are validated.
  • The application is packaged with Docker.
  • Kubernetes manifests are tested locally using Minikube.
  • Terraform configuration is validated.
  • Approved changes are prepared for AWS deployment.
  • Website assets are stored in Amazon S3.
  • CloudFront distributes the website content.

Engineering Lessons

Education websites require particularly clear information architecture. Users should not have to fight the interface to find the information they need. Responsive design, accessibility, performance and content structure therefore become important engineering considerations.

One important lesson is that application engineering and infrastructure engineering should be considered together. A technically impressive deployment is still unsuccessful if the resulting website provides a poor user experience.

Working with Docker and Kubernetes also reinforced the relationship between applications and their deployment environments.

  • Applications can be packaged consistently with containers.
  • Kubernetes introduces structured deployment and service management.
  • Minikube provides a practical local environment for testing Kubernetes concepts.
  • CI/CD should validate changes before deployment.
  • Infrastructure as Code improves repeatability and reduces manual configuration.
  • CloudFront changes how static applications are delivered by distributing content closer to users.
  • Security, performance and cost should be considered during architecture decisions.

Kubernetes Deployment Model

The local Kubernetes workflow helped reinforce how an application moves from source code into a containerized workload and eventually into a Kubernetes-managed environment.

Application → Container → Pod → Deployment → Service → Cluster

CI/CD Engineering Approach

The CI/CD workflow is designed around progressive validation rather than simply deploying every source-code change.

Developer Push → GitHub → Validate → Build → Docker → Security & Quality Checks → Kubernetes Test → Terraform Validation → Production Deployment

Infrastructure as Code

Terraform makes the desired AWS infrastructure explicit and reproducible. Instead of relying entirely on manually configured cloud resources, infrastructure configuration can be version controlled, reviewed and recreated when required.

Cloud Delivery Architecture

Amazon S3 provides the storage layer for the static website assets, while Amazon CloudFront provides content distribution through the CDN. This architecture reduces the need for traditional always-on application servers for a static website.
